# ADR 0004: Prisma ORM with driver adapter against Supabase Postgres

**Status:** Accepted

## Context

The database is Supabase-hosted Postgres. The team wanted a type-safe ORM with migration tooling rather than hand-written SQL or a lighter query builder, given the schema's size (20+ models) and the importance of catching schema/query mismatches at compile time in a financial/invoicing system.

Prisma 7 (the version resolved at install time — considerably newer than most available documentation/training material describes) changed its architecture in ways that materially affect how it's used here:

- `datasource.url`/`directUrl` are **no longer valid inside `schema.prisma`** — connection strings live in `prisma.config.ts` instead.
- The default generator is `prisma-client` (not the classic `prisma-client-js`), outputting to a custom path (`src/generated/prisma`) rather than into `@prisma/client` in `node_modules`.
- The runtime `PrismaClient` requires a **driver adapter** — a bare `new PrismaClient()` no longer reads `DATABASE_URL` from the environment automatically the way older Prisma versions did.

## Decision

- Use Prisma as the ORM, with `@prisma/adapter-pg` (a plain `pg` `Pool`) as the required driver adapter for the runtime client (`apps/api/src/lib/prisma.ts`).
- `apps/api/prisma.config.ts` holds connection configuration: migrations run against `DIRECT_URL` (Supabase's session/non-pooled connection, port 5432 — required for DDL), while the runtime app uses `DATABASE_URL` (Supabase's transaction pooler, port 6543) via the adapter.
- Generated client output goes to `apps/api/src/generated/prisma` (gitignored, regenerated by `prisma generate`), not `node_modules/@prisma/client`.

## Consequences

- Every new environment (a fresh clone, a CI runner, a new contributor's machine) needs both `DATABASE_URL` and `DIRECT_URL` set correctly, with the pooled/non-pooled distinction understood — documented in `apps/api/.env.example`.
- Prisma-related code and documentation written or found online for Prisma ≤6 will describe a different, no-longer-valid schema/config shape (`datasource { url = env(...) }`, `new PrismaClient()` with no adapter) — don't copy such examples without adapting them to this project's actual (Prisma 7) conventions.
- No native query-engine binary is required for basic CRUD (the driver-adapter architecture goes through `pg` directly), which simplifies the Docker image compared to older Prisma versions that bundled a Rust engine binary.
